# QARAVAN Events — events.qaravan.org

Страница со всеми ближайшими событиями для ссылки в Instagram bio: **https://events.qaravan.org**

Хостинг: GitHub Pages (этот репозиторий, ветка `main`). Домен: CNAME-запись `events → ashtyngon.github.io` в DNS-настройках qaravan.org (Wix).

## Как обновить события

1. Откройте [`index.html`](index.html) и нажмите карандаш («Edit this file»).
2. Меняйте только текст в кавычках в списке `EVENTS`. Одно событие — один блок `{ ... }`: добавить — скопируйте соседний и поправьте, отменили — сотрите блок. Дата — в поле `dates` в виде `"ГГГГ-ММ-ДД"`; если дат несколько (как у группы поддержки), перечислите их через запятую. Число, день недели, месяц в шапке и порядок карточек страница считает сама.
3. Нажмите «Commit changes». Сайт обновится сам через 1–2 минуты.

Прошедшие события переносить никуда не нужно — это делает робот (ниже). Список `ARCHIVE` руками не трогайте.

Подробная инструкция продублирована комментарием прямо в `index.html`, перед списком событий.

## Робот: прошедшие события уходят в архив сами

Каждую ночь (4:30 по Нью-Йорку) workflow [«archive past events»](.github/workflows/archive-past.yml) запускает `robot/archive-past.mjs`: он убирает из `EVENTS` всё, что уже прошло, и складывает в `ARCHIVE` по месяцам — прошлые месяцы показываются под текущим списком свёрнутым блоком «Показать». У события с несколькими датами прошедшие даты уезжают в архив, будущие остаются в карточке. Если что-то переехало, робот коммитит `index.html` в `main`, и сайт пересобирается сам. Красный прогон — значит, робот не смог прочитать список (обычно лишняя запятая или кавычка в `EVENTS`); сайт при этом не ломается, просто прошедшее остаётся наверху до починки.

Запустить сейчас: Actions → «archive past events» → Run workflow (галочка «Dry run» — только показать, что переедет). Локально: `node robot/archive-past.mjs` (`TODAY=2026-10-01` — притвориться, что сегодня другой день; `DRY_RUN=1` — не записывать файл).
